## 2. 阶段 1 · 门户(Astro)

### 任务拆解

| # | 任务 | 验收标准 |
|---|------|----------|
| 1.1 | 初始化 Astro 工程(TS + Vue + Tailwind) | `npm run dev` 可跑,Tailwind 样式生效 |
| 1.2 | 设计 token 落地(global.css + tailwind.config) | 03 规范中所有 token 有对应 CSS 变量 |
| 1.3 | BaseLayout + Nav + Footer | 全站导航高亮正确;移动端汉堡可用 |
| 1.4 | Hero + 首页 | 深色渐变 + 网格/粒子;三业务线卡片从 content 自动渲染 |
| 1.5 | content collections(business/docs) | 构建期类型校验通过;缺字段报错 |
| 1.6 | 业务线动态路由 `[slug]` | 三个 slug 均生成页面;accent 随内容切换 |
| 1.7 | RegisterForm.vue(报名岛) | 三线报名页可用;调 04 契约接口(未部署后端时走 mock 开关) |
| 1.8 | FeedbackBox.vue(反馈岛) | 每页底部可提交;page 字段正确 |
| 1.9 | 长文档迁移(学习规划/运营方案) | HTML → md + Mermaid;流程图渲染与缩放正常 |
| 1.10 | 404 页 + SEO meta | 404 有引导;每页 title/description |

### 里程碑
M1:1.4 完成 → 首页视觉 demo(给运营/社团看风格)
M2:1.9 完成 → 门户功能全量可用(后端 mock)

### 关键风险
- 学习规划原 HTML 含大量手工 SVG/交互,md 化可能丢失 → 对策:先迁正文+流程图,特殊交互以 iframe 嵌原 HTML 兜底(02 技术设计 §6)
- Vue 岛与 Tailwind 版本兼容 → 用 Astro 官方集成,锁定版本

## 3. 阶段 2 · 后端(yudao)

### 任务拆解

| # | 任务 | 验收标准 |
|---|------|----------|
| 2.1 | 拉取 yudao-boot 工程,本地跑通 | 管理后台可登录,基础菜单正常 |
| 2.2 | Maven 裁剪(pom 只留 system/infra) | 启动无 ClassNotFound/Bean 报错 |
| 2.3 | 建 club 模块 + 4 表(代码生成器) | 后台出现 club 四个菜单,CRUD 可用 |
| 2.4 | 报名/反馈接口加 @PermitAll + SaToken 放行 | curl 匿名可调通,数据落库 |
| 2.5 | 限流(@RateLimiter) | 连发 6 次返回 429 |
| 2.6 | 状态流转 + Excel 导出 | 后台可流转状态、导出筛选结果 |
| 2.7 | 生产环境裁剪(关 codegen/swagger/MQ/XXL-JOB) | 生产 profile 启动正常 |
| 2.8 | 运营账号 + 权限(仅 club 菜单) | 运营登录只见社团运营模块 |

### 里程碑
M3:2.4 完成 → 门户可接真实接口
M4:2.8 完成 → 后台可用

### 关键风险
- 裁剪后启动报错 → 按"删依赖→编译→启动"小步走,每次只删一个模块;system/infra 不动(02 §3.1)
- yudao 版本与 JDK/MySQL 兼容 → 用 yudao 官方推荐的版本组合,不追新

### 任务拆解

| # | 任务 | 验收标准 |

| 3.6 | 运营培训(半小时) | 运营能独立完成:改公告/看报名/导出/看反馈 |

### 里程碑
M5:3.2 完成 → 全站公网可访问
M6:3.6 完成 → 交付运营

### 验收清单(对照 PRD §7)

- [ ] 桌面 + 移动端全部页面无样式错乱,首屏 < 2s
- [ ] 三线报名独立提交、后台筛选/导出/状态流转正常
- [ ] 反馈从任意页提交,后台可见来源页
- [ ] 运营仅一个后台完成全部日常操作
- [ ] yudao 裁剪版 2C4G 稳定运行 ≥ 7 天无 OOM
