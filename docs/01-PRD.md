# 01 · 需求规格说明书(PRD)

> 版本:v1.0 ｜ 状态:评审稿 ｜ 日期:2026-08-19
> 配套:02-技术设计、03-设计规范、04-接口契约、05-实施计划

---

## 1. 背景与目标

福州大学 AI+社团现有三条业务线(AI+IT / AI+业务 / AI+嵌入式),需要一个统一的集成门户承载:

- **信息展示**:社团介绍、业务线介绍、学习规划、运营方案
- **报名**:招新报名(三线独立表单)
- **反馈**:访问者对任意页面的建议收集
- **服务入口**:QQ 群 / 微信 / 邮箱 / 资源链接

原站点托管于 Coze,已迁移到自有服务器(2C4G)。本次按"门户 + 运营后台"两段式重建,门户追求**美观惊艳**(代表社团技术实力),运营后台追求**稳定易用**。

**一句话目标**:一个让访问者觉得"这个社团很厉害"的门户 + 一个让运营"五分钟学会"的后台。

## 2. 用户角色

| 角色 | 是谁 | 核心诉求 | 接触面 |
|------|------|----------|--------|
| 访问者 | 在校学生(潜在成员) | 快速了解社团、报名加入 | 门户(全部页面) |
| 运营 | 社团干事(非技术) | 改公告、看报名、看反馈、导出 | yudao 后台 |
| 技术组 | 社团内学开发的学生 | 维护网站、迭代功能 | 门户代码 + yudao 工程 |
| 管理员 | 技术组负责人 | 账号分配、权限管理 | yudao 后台 |

## 4. 非功能需求

| 维度 | 要求 |
|------|------|
| 性能 | 门户首屏 < 2s(静态构建,零/极少 JS 首屏) |
| 视觉 | 现代科技感,对标 Linear/苹果产品页;三业务线有清晰品牌色 |
| 兼容 | 桌面 + 移动端(断点 768px/480px),主流浏览器 |
| 安全 | 报名/反馈接口限流;后台强密码;MySQL/Redis 不对外网开放 |
| 可维护 | 门户零构建负担(Astro 构建一次出静态);运营零技术门槛;文档齐全 |
| 可扩展 | 新增业务线 = 加 content + 加后台记录,核心代码零改动 |
| 可观测 | 门户 /healthz;后端 /actuator/health;日志分级带模块 tag |

## 5. 范围边界

### 一期(本次交付)
- 门户:Astro 全量重写(首页/三业务线/报名/反馈/长文档迁移)
- 后台:yudao 裁剪版 + club 模块(报名/反馈 CRUD + 导出)+ 运营账号
- 公告:门户用 `content/site.json`(后台公告管理二期接入)

### 二期(预留,不阻塞一期)
- 公告/业务线配置改为后台下发(门户通过 API 拉取)
- SEO 优化(meta/OG 标签完善、sitemap)
- 更多业务线接入(流程已定义好)
- 门户访问统计(自建轻量埋点或接第三方)

## 6. 页面清单(信息架构)

```
/
├── 首页(/)                       # Hero + 三业务线卡片 + 公告
├── business/
│   ├── ai-it/                    # AI+IT 主页
│   ├── ai-it/learning-plan/      # 学习规划长文档
│   ├── ai-it/register/           # AI+IT 报名
│   ├── ai-biz/                   # AI+业务 主页
│   ├── ai-biz/register/          # AI+业务 报名
│   ├── ai-embed/                 # AI+嵌入式 主页
│   └── ai-embed/register/        # AI+嵌入式 报名
├── ops/                          # 运营方案(内部文档,入口不对外导航)

```

后台(独立路径 `/admin`):登录 → 社团运营(业务线/公告/报名/反馈)+ 系统管理(用户/角色/菜单)

## 7. 验收标准(摘要,详见 05-实施计划)

1. 门户所有页面在桌面/移动端无样式错乱,首屏 < 2s
2. 三业务线报名各自独立提交,后台可筛选、可导出、可流转状态
3. 反馈从任意页面可提交,后台可见来源页
4. 运营仅登录一个后台完成"改公告/看报名/看反馈"全部日常操作
5. yudao 裁剪后启动无报错,内存占用可控(2C4G 可跑)
